1半年的工作规划

分阶段说明重点工作、解决问题、交付成果，以及优先级安排逻辑。

前三个月 · 人效提升

主流程：保持现有财务主流程不变。

重点：用 RPA、半人工、已接通 API，把数据收集与初加工效率提上来；计算侧同步迁入云服务器 / 云数据库 / 大数据计算引擎分层体系。

交付：关键导出链路人效提升；已接通平台营业额天结果表；费用审批等完成 ODS→DWD；公共维度起步建设。

半年度 · 系统化方案

主流程：关键节点去人工依赖，形成可运行的系统能力。

重点：系统自动解决关键人工节点；管理报表与业务数据融合；跨境进销存与货值供应链可靠性完善；评估资金清分平台。

交付：经营上财务与业务融合的管理模式；更多链路 API 自动入仓；货值与全平台营业额系统化输出。

阶段 解决什么问题 预期成果
M1–M3 数据收集工作量大；本地库与本地 Excel 加工导致效率低、数据留存与协同差；人工核算与二次清洗耗时长 收集侧自动化/半自动化；云端分层跑通；出表准备时间缩短，主流程不被打断
M1–M6 关键节点依赖人工；财务与业务是否有效融合尚不清晰；跨境与货值等经营闭环不完整 关键自动化；管理报表与业务一体；跨境进销存与货值等系统化能力落地

优先级安排

  1. 先保出表节奏与人效，主流程不动 — 避免改革初期打断财务关账与管理报表。
  2. 收集用 RPA、计算用云仓并行 — 对应「18 号出表」的两大根因。
  3. 费用归属先制度与人工严控，平台化半年评估 — 审批流改造前保证填报与审核质量，再决定资金清分平台。
  4. 跨境进销存、全平台营业额、货值供应链放半年度 — 依赖主数据与多方协同，适合系统化阶段。

2财务自动化的落地方案

说明如何推进，涉及哪些数据源、数据处理与核算环节，如何与现有财务流程衔接，以及如何验证结果准确性；并给出分项落地与货值专项。

效率目标

月度管理报表 / 利润报表：现状约 每月 18 号 出具 → 逐步提前到 每月 10 号。

财务协同输入

提供「无法在每月 10 号前提交、影响关账的事项清单」。能提前的协调数据方提前给数；实在给不出的，采用预估数据先出一份。

2.1 如何推进

按「双路径、两阶段、先并行不改主流程」推进：

  1. 双路径并行：数据收集侧用 Codex 实现爬虫/RPA + 影刀 10 账号持续运行（无更好 API 时）把人工拉取改为定时自动执行，并按效果补充完善；计算核算侧用 云服务器 + 云数据库 + 大数据计算引擎，把本地处理、人工二次清洗与复杂规则计算迁到云仓分层作业。
  2. 前三个月：财务主流程不变，只替换「取数慢、算数慢」的环节；先打通资金账单、店铺账单、费用审批、已接通平台营业额等可快速见效链路。
  3. 半年度：关键节点去人工，补齐跨境进销存、全平台营业额、货值供应链，并评估资金清分平台，形成财务与业务融合的系统化能力。
  4. 制度与系统同步：费用归属在改造审批流前，先要求业务准确选择、财务严格审核；预估规则先与财务确认科学性，再固化为定时计算任务。
  5. 盘点驱动补缺：运营输出 API/系统清单，财务输出关账阻塞清单；发现覆盖缺口则制定获取方案（申请 API、移交权限、协调提前给数或预估）。

2.3 数据处理和核算环节

端到端按「采集 → 入仓 → 清洗关联 → 规则核算 → 结果表 → 管理报表」运转：

环节做什么产出
1. 采集 RPA / API / 半人工按日或定时取数；资金账单允许重复入库 原始文件或接口报文落入云端
2. ODS 原始层 原样落库，保留溯源；不在此层做业务口径改写 可追溯的原始事实表
3. 清洗去重（DWD） Python/SQL 合并、清洗、去重；字段标准化；挂接品牌、币种等维度 明细层事实表（一笔业务一条清晰记录）
4. 公共维度（DIM） 金蝶、钉钉、聚水潭、领猫等按管理口径自动计算公共维度表 品牌、币种、仓库、供应商等统一维表
5. 核算与规则计算 在云仓固化管理核算规则：费用归因、科学分摊、加权成本、头程预估分摊至 SKU、预估报表规则等；减少本地 Excel 人工核算 可复算、可审计的中间核算结果
6. DWS / 天结果表 汇总输出营业额天表、预估结果表、货值相关结果、核对用明细等 直接服务月度管理报表与日常经营看数
7. 对账与预估闭环 资金流水与业务对账；费用与资金核对；10 号前对阻塞项用预估补齐，实数到达后按规则回写/替换 可按期出表，同时保留实数校正路径

2.4 如何与现有财务流程衔接

图 3 · 与现有财务关账 / 出表流程衔接

财务侧
既有关账节奏 管理报表编制 归属审核 / 规则确认 阻塞清单维护
IT 侧
日调度取数入仓 清洗核算出结果表 预估补齐阻塞项 按节点向财务供数
  1. 前三个月不改财务主流程：关账职责、报表责任人、审批链路仍在财务；IT 只把「等人送数 / 本地慢算」改成「云端按时就绪」。
  2. 按财务节点供数：以财务月度关账与管理报表编制节点为对齐点；日常以天结果表持续刷新，月度取数窗口前保证所需明细与汇总已产出。
  3. 阻塞项专项衔接：财务列出无法在 10 号前提交的事项；IT/业务协调数据提供方提前给数；仍无法提供的，按约定预估规则先出表，保证编制工作可启动。
  4. 费用链路衔接：改造审批流前，业务在钉钉准确选择归属等信息，财务严格审核；IT 同步落 ODS–DWD，审核后的数据进入核算与核对，避免「系统有数但归属不可用」。
  5. 预估报表衔接：现行预估规则先由财务确认科学性，再由 IT 做成定时预估结果表，嵌入现有「先预估、后实数」的管理习惯，而不是另起一套口径。
  6. 输出形态衔接：结果表可供财务沿用既有报表结构取数；BI（帆软或 Quick BI）用于查看与核对，不强制财务立刻更换编制工具。

2.5 如何验证结果的准确性

校验类型做法责任方
采集完整性 账户/店铺/任务是否跑成功；条数、金额合计与源端抽查比对；RPA 失败告警重跑 IT 主责，出纳/运营协助抽查
清洗去重正确性 ODS 与 DWD 笔数、金额勾稽；重复键是否按规则合并；异常明细清单复核 IT
费用归属准确性 审批单必选归属信息；财务审核通过后方可进入正式核算口径；抽查归属与业务实际是否一致 业务填报 + 财务审核，IT 固化校验规则
核算规则一致性 分摊、加权成本、费用归因、头程分摊等规则先书面确认再上线；同一输入重跑结果应一致（可复算） 财务确认规则，IT 实现与回归
预估科学性 上线前与财务确认预估规则；上线后对比「预估值 vs 后期实数」，偏差纳入规则迭代 财务 + IT
资金与业务对账 资金流水、店铺账单、费用审批、销售等交叉勾稽；差异清单定位到明细 财务主导核对，IT 提供对账结果表
货值勾稽 采购流水、在库/在途数量、SKU 天成本、头程分摊可串联核对；日快照支持回溯 供应链 + 财务抽查，IT 提供链路
平行验证（切换期） 前三月主流程不变期间，云仓结果与现行手工/本地结果并行对比，差异清零或解释后方可作为正式供数 IT 出对比，财务签字确认
准确性总原则：源端可追溯（ODS）→ 明细可勾稽（DWD）→ 规则可复算（核算作业）→ 财务可确认（平行对比与审核）。未通过平行验证的结果表，不替代财务正式出表取数。

3技术方案和现有 IT 资产的处理

暂不建设完整大型数据平台，但底座必须可扩展、可运维，避免短期方案无法持续。

3.1 存储与计算改造原则

当前以本地电脑数据库承载企业数据的方式，不利于重要信息与数据的安全留存、备份与协同。半年度明确改为 云服务器 + 云数据库 + 大数据计算引擎 作为正式数据底座；本地机器仅作为 RPA 采集端或临时加工端，不作为企业主数据存档位置。

已申请的电商等开放平台 API / 账号 续用并盘点补齐 目前部分由运营管理。运营协助输出《开放平台 API 清单》《业务在用系统账号密码/管理员清单》，评估是否覆盖财报与经营支撑；缺口制定获取方案。
金蝶、钉钉、聚水潭、领猫 续用 + 加强 API 集成 作为公共维度与业务事实的主来源；领猫为现行采购系统，服务货值与采购流水。
本地电脑数据库 / 大量本地 Excel 加工 调整下线为主存 迁移至云服务器、云数据库与大数据计算引擎；本地仅保留采集与临时用途。
帆软 BI 优先续用 核对合同：若现公司已购买且可用则继续使用；否则按月采购 BI（Quick BI 高级版 10 用户）。
云服务器 / 大数据计算 / 云数据库 / 调度集成 明确新增（或扩容为正式底座） 按量最低可运行配置起步，支撑 ODS–DWD–DWS 与日调度。
RPA / 采集自动化与机房台式机 新增 以 Codex 实现爬虫 / RPA 效果并持续补充完善；同步采购影刀 RPA 10 个账号持续使用；台式机一次性先采购 1 台。
资金清分平台 半年度评估（可能外采） 用于自动凭证、资金清分等未来能力，不作为前三月必建项。

3.3 数据结构逐步完善路径

  1. 先落 ODS 原始事实（允许重复），保证「有数可溯」。
  2. 再建 DWD 明细与公共 DIM，统一品牌、币种、仓库、供应商等口径。
  3. 输出 DWS / 天结果表服务营业额、预估、货值等管理场景。
  4. 半年度补齐跨境与供应链深度主题，避免一上来建设过重平台。

    云底座建设（云服务器、大数据计算引擎、云数据库、调度）
    依赖：采购开通。所有 ODS/DWD/结果表的技术前提；替换本地库主存。
  • 04
    公共维度 DIM（金蝶 / 钉钉 / 聚水潭 / 领猫）
    依赖：03 + 01。为明细关联与管理口径统一提供维度。
  • 05
    资金账单 RPA 入仓
    依赖：03；台式机、Codex 实现与影刀 10 账号。解决 200+ 账户收集瓶颈。
  • 06
    店铺账单 RPA 入仓
    依赖：03；可与 05 并行。
  • 07
    费用审批钉钉集成（ODS–DWD）+ 归属填报规范
    依赖：03、04；财务/业务协同。费用归属质量门禁。
  • 08
    销售 + 库存半人工提效
    依赖：03；可与 05–07 并行。
  • 09
    营业额天结果表（已接通平台）
    依赖：03、04、相关销售入仓。前三月可先交付已接通范围。
  • 10
    预估报表规则确认与系统预估结果表
    依赖：02（阻塞与预估范围）、09 及费用/成本相关输入。

    依赖：05、07 有稳定明细后；半年度再叠加自研与 OA 规范。
  • 12

    依赖：03、08 经验复用、跨境平台 API（01 盘点结果）。
