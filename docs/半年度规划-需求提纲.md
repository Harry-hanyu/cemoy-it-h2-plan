## 1. 半年的工作规划（阶段框架已定）

| 阶段 | 思路 | 主流程 | 重点交付方向 |
|------|------|--------|--------------|
| **前三个月（M1–M3）** | 提升 **人效** | **当前主流程不变** | RPA / 半人工 / 已接通 API → 云仓；压缩收集与初加工人时 |
| **半年度（M1–M6）** | **系统化** 解决方案 | 关键节点去人工 | 系统自动解决关键依赖；管理报表与业务 **经营融合**（当前是否有效融合尚不清楚 → 半年度要解决） |

优先级逻辑（写正文时展开）：

1. 先保出表节奏与人效（不打断现财务主流程）  
2. 并行把「收集」用 RPA、「计算」用云仓两条腿落地  
3. 费用归属、口径、OA 规范等半人工管控先行，平台化方案半年评估  
4. 跨境进销存 / 货值 / 全平台营业额等系统化能力放半年度

## 2. 财务自动化的落地方案（摘要）

**效率目标：** 管理报表约 **18 号 → 逐步提前到 10 号**

**18 号根因 → 技术路径：**

| 根因 | 方案 |
|------|------|
| 1. 数据收集工作量大 | **RPA** |
| 2. 计算处理成管理报表难（本地处理、人工核算、二次清洗、复杂分摊/加权成本/费用归因、口径与 OA、预估与资金对账等） | **云数据仓库** |

**财务协助清单（已定）：** 「无法在每月 10 号前提交、影响关账的事项清单」→ 协调提前给数；给不出则 **预估** 先出表。

**数据导出子项节奏（摘要）：**

| 子项 | 前三个月 | 半年度 |
|------|----------|--------|
| 资金账单（200+ 账户） | 评估出纳步骤；无好 API 则机房台式机 + RPA 定时 → 云数据集；ODS→DWD+DIM | 与公共 DIM / 清分等深化 |
| 费用审批单 | 钉钉 API → ODS–DWD；业务准确选归属 + 财务严审 | 评估自研+外采 **资金清分平台**（自动凭证、清分） |
| 销售+库存 | 半人工；RPA+API+云仓 | **跨境进销存** API 入仓；ODS–DWD–DWS 天表 |
| 店铺账单 | RPA 提效 | API 自动进云仓 |
| 资金结余 | 评估；不影响出表则仍「泗洪人工」（待确认含义） | 评估外采资金清分平台 |

**月度报表子项节奏（摘要）：**

| 子项 | 前三个月 | 半年度 |
|------|----------|--------|
| 营业额 | 已接通平台 → 中台 **天结果表** | 全平台销售额系统化天表 |
| 预估报表 | — | 评估规则科学性 → 与财务确认 → 大数据定时预估结果表 |
| 费用/资金核对 | 提效 | 自研 + 完善钉钉 OA + 规范制度 |
| 货值 | — | 供应链可靠性：采购流水、供应商、仓层级、在库/在途、SKU 天成本、头程预估分摊 |

**公共底座：** 金蝶 / 钉钉 / 聚水潭 / 领猫 API → 定时集成 → 管理口径 **公共 DIM**；分层 ODS→DWD（+DWS/天表）。

## 3. 技术方案和现有 IT 资产的处理

结合 **瀚章介绍的现状**（待补充/引用），说明：

- 哪些现有程序、数据库、报表、系统可继续使用
- 哪些需调整或重构
- 哪些确有必要新增
- 数据采集、存储、清洗、关联、计算路径
- 底层数据结构如何逐步完善

**原则约束：**

- 暂不要求直接建设完整大型数据平台
- 需考虑后续业务扩展，避免短期方案无法持续维护

**与财务方案对齐的技术取向（已口述）：**

- 采集：RPA（机房台式机）+ 各开放平台/业务 API  
- 存储计算：企业云数仓 / 数据中台分层（ODS–DWD–DWS）  
- 维度：公共 DIM（品牌、币种等）  
- 半年可选增量：资金清分平台（自研+外采）、跨境平台 API、自研核对/OA 增强  

**运营侧现状与需协助事项（已定）：**

- 现状：运营管理部分 IT 资产（电商平台已申请 API 密钥/账号密码）
- 产出：《开放平台 API 清单》《业务在用系统账号密码/管理员清单》
- 目的：盘点是否覆盖财报与经营支撑；缺口则制定获取方案
